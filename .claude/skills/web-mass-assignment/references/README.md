## The evidence pipeline

1. **control** request — the documented body;
2. **canary** request — ONE extra field;
3. **read-back** — `GET` through a DIFFERENT endpoint;
4. **decision exercise** — hit the gate the field controls.

`readback-protocol.md` is the formal protocol; `evidence-rules.md` +
`evidence-map.md` are the confirm/falsify standard; `falsifiers.md` +
`per-falsifier.md` are the kill-map.

## The tool

`tools/web/binding_probe.py` — the field-matrix runner:

```bash
python3 tools/web/binding_probe.py --url "$BASE/api/register" \
  --body 'username=p&password=x' --readback "$BASE/api/me"
```

Default field set: `role`, `admin`, `is_admin`, `isAdmin`, `debug`,
`permissions`, `group`, `verified`, `is_staff`. `--fields` overrides;
`--method GET` tests query; `--headers` carries auth; `--selftest`
proves it offline.

## The probe order

```
endpoint: PATCH /me → PUT → POST/register → orders → import → GQL → admin
field:    privilege → verify → econ → plan → ownership → workflow → internals
carrier:  flat → nested → form → prefixed → array → typed → PUT → override
```

The widest binder + highest-value semantic + least-tested carrier.

General guidance — no solved chain in this toolkit yet.
