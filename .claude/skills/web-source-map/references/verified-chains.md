# Verified chains — honest status

## This repository

`web-source-map` is a **catalogue** class — nothing in this toolkit has
solved a challenge whose mechanism was front-end bundle/source-map
recon as the leading technique. The corpus here is standard published
knowledge, not local experience.

When a real solve lands — a challenge where the map or bundle supplied
the endpoint, key, or flag that won — record it in `../field-notes.md` and
the chain card promotes the class to verified.

## The honest posture

Do not present the shapes in `case-studies.md` as "what worked here".
They are the standard map-mining playbook. The evidence-level field in
`../SKILL.md` (absent → catalogue) is the honest marker; the solved-chain
count in `knowledge/chains/` is the record.

## What would verify it

A challenge where `bundle_miner` (or a manual `.map`/string pass) was
the decisive recon — the endpoint, key, route, or flag came from the
bundle and the solve followed. Then the class earns `verified` and the
card records the exact signal that led to the find.

## Adjacent verified work

The bundle-as-spec lesson already appears in verified chains — reading
the front-end JavaScript for the route table and the dead-code
constants is standard recon in this repository. `web-source-map` is
that practice made explicit and tooled (`bundle_miner`), not a new
class — its promotion needs a solve where the map/mining step itself
was the named mechanism.
