# The identity-pivot workflow — one pivot, an ordered plan

The pivot is a handle/email/name/key and the question asks for a
DIFFERENT attribute of the same identity — another account, a real
name, a location, a domain.

## The order

1. Extract the single most UNIQUE pivot and normalise it — a key
   fingerprint computed, not eyeballed; an email pattern derived,
   not guessed.
2. An ordered plan of at most six queries, each with its source and
   the one fact it would confirm.
3. Work one source at a time; verbatim results into notes.
4. Corroborate — two attributes that agree make an identity.

## The discipline

A pivot answer is a lead until two attributes corroborate — never name an identity from a handle match alone.
