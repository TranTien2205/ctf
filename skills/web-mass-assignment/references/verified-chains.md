# Verified chains — mass-assignment solves in this toolkit

## Status: catalogue — none yet

This class has **no verified chain card** in `knowledge/chains/` — no
challenge of this class has been solved here. Everything in this
corpus is standard published knowledge, not local experience; treat
every technique as a starting point and record what actually happens.

## When a solve lands

`classify_solve.py --chain <id>` files the solve into this class —
which promotes `web-mass-assignment` from `evidence_level: catalogue`
to `verified` and writes the first field-note entry. Until then, the
class is unproven here.

## What the first card will need

- the endpoint and carrier that bound the field;
- the bound field's name and value;
- the read-back proving storage;
- the decision the field changed (the gate/route/total);
- the falsifiers observed en route (the dead cells);
- the `blast_radius` if the write touched shared state.

## The catalogue's confidence levels

- **high**: the two-observation protocol (control/canary/read-back/
  decision) — standard methodology;
- **medium**: the field names and carrier shapes — framework-dependent;
- **low**: the specific payloads — per-schema, per-target.

Record every probe result honestly — the first verified card comes
from a real solve, not from the corpus's predictions.
