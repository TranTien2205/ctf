# `pohlig-hellman` — dlog on smooth orders

## When it applies

`h = g^x mod p` where `ord(g)` (or `p-1` for primitive `g`) factors into
small primes. Check first — always:

```bash
python3 tools/crypto_attack.py smoothness --n <order>
```

`smoothness` returns the factorization and the largest prime factor.
A largest factor under ~2⁴⁰ is tractable; much larger → index calculus
territory, not this tool.

## The command

```bash
python3 tools/crypto_attack.py pohlig-hellman --g 2 --h 17 --p 101 --order 100
```

`--order` is `ord(g)` — if the handout gives `p` only and `g` is a generator,
`ord(g) = p-1`. The tool computes the order first, so a generator of a
proper subgroup doesn't produce a wrong coset representative.

In code:

```python
from tools.crypto import dlog
x = dlog.pohlig_hellman(g, h, p, order)
```

## The math

For `ord(g) = Π q_i^{e_i}`:

1. Solve `x mod q_i^{e_i}` — decompose into `e_i` BSGS steps of size `q_i`.
2. CRT the residues → `x mod ord(g)`.

Cost is dominated by the largest prime factor — hence the smoothness gate.

## On curves

The same algorithm applies to `Q = x·P` on `E(Fp)` with smooth `#E` —
`dlog.py` works on multiplicative groups; for curves reuse the same
per-factor logic with point arithmetic via `tools/crypto/ec.py`. But the
smoother path: if `#E` is smooth, the challenge almost always intends PH.

## Preconditions

- Correct `order` — a wrong order gives a wrong `x` that fails verify.
- `h` in the subgroup generated by `g` — `pow(h, order, p) == 1` for
  finite-field cases.

## Falsifier

`pow(g, x, p) != h` after recovery:

- `order` wrong → re-derive `ord(g)` from the factorization.
- `g` isn't a generator of the subgroup `h` lives in →
  find `ord(h)` and solve in that subgroup.
- The order's largest prime factor too big → the solve stalls in one factor's
  BSGS; that's index calculus, not PH.

## Common mistakes

- Using `p` as `--order` instead of `p-1` or `ord(g)`.
- Skipping `smoothness` — PH on a 200-bit-largest-factor runs forever.
- Expecting PH on a safe-prime group (`p-1 = 2q`, `q` large prime) — that's
  the designed-resistant case; the challenge probably wants a different bug.
